# EDAN.Tensor 상용 운영 준비 기준

이 문서는 제품 공통 구현과 고객사별 운영 인수의 경계를 정의한다. 저장소에는 공통 규칙, 자동 검증, 실행 절차만 기록하며 고객사의 실제 비밀번호, Secret URI, 백업 위치, 내부 호스트명, SLA 값은 저장하지 않는다.

## 1. Secret Manager와 자격 증명

- 운영 환경은 평문 비밀번호와 토큰을 환경 파일에 저장하지 않는다.
- 애플리케이션은 Secret Manager에서 읽은 값을 환경 변수 또는 파일 어댑터로 주입한다.
- Secret은 생성·조회·회전·폐기 이력을 감사 로그에 남긴다.
- 회전 후 API, Worker, 테넌트 DB 연결, 백업 작업을 순서대로 재검증한다.
- 고객사 인수 증적: Secret Manager 연결, 최소 권한, 회전 성공, 폐기된 Secret 사용 차단.

## 2. 백업·복구

- SME 기본 프로필은 SQLite 파일 백업과 원자적 스냅샷을 사용한다.
- Enterprise 프로필은 PostgreSQL의 네이티브 백업/PITR과 별도 저장소 복제를 사용한다.
- 고객 업무 DB는 해당 제품(PostgreSQL, SQL Server, Oracle)의 네이티브 백업 정책을 따른다.
- 복구는 파일 존재 확인이 아니라 새 격리 환경에서 애플리케이션 기동, 마이그레이션, Health, 핵심 조회까지 수행해야 한다.
- 고객사 인수 증적: 마지막 백업 시각, 복구 시각, RPO/RTO, 복구 후 정합성 결과.

기준 절차는 [플랫폼 백업·복구 런북](platform-database-backup-restore.md)을 따른다.

## 3. Enterprise HA와 장애 전환

- API는 무상태 복제 가능하게 운영하고 로드밸런서의 readiness를 사용한다.
- Worker는 중복 실행 방지용 lease와 재시도 정책을 사용한다.
- DB는 고객사의 HA 제품과 연결하고, 장애 전환 후 연결 풀 재생성과 Health 회복을 확인한다.
- 장애 전환 중복 DML, 중복 작업, 미완료 보상 기록을 확인한다.
- 고객사 인수 증적: 노드 장애, DB 전환, 네트워크 단절, 복귀 시나리오별 성공 시간과 데이터 정합성.

## 4. 성능과 용량

공통 기준값은 출발점이며 고객사 계약 SLA가 우선한다.

| 프로필 | 기준 동시 사용자 | 기준 처리량 | 기준 응답시간 |
|---|---:|---:|---|
| SME | 20 | 5 RPS | p95 2초 이하, p99 5초 이하 |
| Enterprise | 100 | 25 RPS | p95 1초 이하, p99 3초 이하 |

테스트에는 인증, 테넌트 해석, 업무 DB 메타데이터, Routine 호출, 실패 재시도, 감사 로그를 포함한다. 결과에는 CPU, 메모리, DB 연결 수, 오류율, p95/p99, 포화 시점을 기록한다.

## 5. 관제·알림·SIEM

- 구조화 로그에는 Request ID, Tenant ID(민감정보 제외), 작업 유형, 결과, 지연시간을 포함한다.
- 인증 실패, 테넌트 경계 위반, Secret 오류, DB 장애, 재시도 소진, 보상 실패를 경고한다.
- OpenTelemetry를 애플리케이션 표준으로 하고, Prometheus/Grafana 또는 고객사 동등 도구로 수집한다.
- SIEM 전송은 고객사 보안정책에 맞추며 토큰·비밀번호·업무 데이터는 마스킹한다.
- 고객사 인수 증적: 대시보드, 알림 수신, 로그 보존, SIEM 수신 및 장애 알림 테스트.

## 6. 런타임 프로필 강제

- SME: SQLite 기반, 단일 설치를 기본값으로 한다.
- Enterprise: PostgreSQL 기반, External HTTPS IdP, 고가용성·백업 정책을 명시한다.
- Production에서는 인증 우회, HTTP 메타데이터, 평문 연결 문자열을 거부한다.
- 프로필 검증 스크립트와 상용 완료 게이트를 배포 전에 실행한다.

## 7. 고객 업무 DB 보안

- 테넌트별 연결 정보는 플랫폼 DB의 바인딩과 Secret 참조로 관리한다.
- 업무 DB 계정은 메타데이터 조회와 허용된 Routine 실행에 필요한 최소 권한만 갖는다.
- 임의 SQL 실행은 제공하지 않고 Routine Allowlist, 파라미터 스키마, 실행 감사 로그를 사용한다.
- PostgreSQL, SQL Server, Oracle에서 계정·스키마·Routine 권한을 자동 점검한다.

## 8. 장애·재해복구 리허설

최소 시나리오는 API 재시작, Worker 중단, DB 연결 단절, Secret 회전, 백업 복구, IdP 일시 장애, 고객 DB 장애, 네트워크 분할이다. 각 시나리오마다 감지, 완화, 복구, 정합성 확인, 사후 보고서를 남긴다.

## 추가 상용 보강 기준

- SBOM 생성 및 이미지·의존성·SAST/DAST 취약점 검사.
- 개인정보·토큰·연결 문자열 마스킹과 보존·삭제 정책.
- 설치·업그레이드·롤백 자동화 및 마이그레이션 사전 검증.
- 릴리스별 테스트, 보안 검사, 백업 복구, 장애 리허설 결과를 인수 증적으로 보관.

## 완료 판정

저장소 공통 구현과 자동 게이트가 통과하면 “제품 공통 상용 준비 완료”로 판정한다. 실제 고객사 Secret Manager, 백업 저장소, HA 장비, 성능 목표, 관제/SIEM은 고객사 환경에서 증적을 제출하기 전까지 “고객사 운영 인수 대기”로 판정하며, 이 상태는 코드 완료와 혼동하지 않는다.
