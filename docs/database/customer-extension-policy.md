# 고객사 프로젝트 확장 정책

고객사 선정 후 추가되는 업무 테이블은 제품 기준 스키마와 분리된 확장으로 관리한다.

## 허용 방식

- 기준 테이블은 수정하지 않는다.
- 고객 확장 테이블은 `ed_10001`부터 번호를 예약한다.
- 고객 확장 컬럼과 관계는 별도 마이그레이션으로 추가한다.
- 고객 전용 Routine은 Allowlist에 등록하고 실행 감사 로그를 남긴다.
- 고객 전용 화면·메뉴·버튼·역할은 SYS 권한 모델을 사용한다.
- 고객별 실제 DB·Secret·SLA는 운영 설정과 인수 문서에만 기록한다.

## 금지 방식

- 제품 기준 테이블에 고객사 컬럼을 임의로 삽입
- 고객사 업무 테이블을 `ed_00001`~`ed_01999`에 생성
- API에서 임의 SQL을 직접 실행
- 고객 비밀번호나 Secret을 Git에 저장
- 고객별 변경을 공통 마이그레이션에 섞기

## 프로젝트 완료 산출물

1. 고객 확장 ERD와 테이블 명세서
2. 확장 마이그레이션과 롤백 계획
3. API 계약 및 권한 매트릭스
4. Routine Allowlist와 최소 권한 점검 결과
5. 데이터 이관·백업·복구 계획
6. 성능·보안·운영 인수시험 결과
