# Edan 기준 스키마 동결본

이 문서는 고객사 선정 전에 공통으로 제공하는 Edan 업무 데이터베이스의 기준 범위다. 고객사 업무 테이블은 이 목록에 직접 추가하지 않고 고객 프로젝트 확장 영역으로 관리한다.

## 데이터베이스 역할

`EdanFramework`는 Tensor 운영·라이선스·테넌트·DB 바인딩을 관리한다. `Edan`은 고객사 업무 사용자를 위한 시스템 정보(SYS)와 기준정보(BAS)를 관리한다. 두 영역은 권한과 연결 정보를 분리한다.

## 기준 테이블 목록

| 영역 | 번호 | 물리 테이블 | 논리명 | 주요 용도 |
|---|---:|---|---|---|
| SYS | 00001 | `ed_00001` | 메뉴 | 메뉴 계층과 화면 경로 |
| SYS | 00002 | `ed_00002` | 버튼 | 메뉴별 실행 권한 대상 |
| SYS | 00003 | `ed_00003` | 역할 | 고객 시스템 역할 |
| SYS | 00004 | `ed_00004` | 역할 권한 | 역할-버튼 권한 연결 |
| SYS | 00005 | `ed_00005` | 공통코드 | 코드 그룹과 코드 일람표 |
| BAS | 01001 | `ed_01001` | 회사 | 고객 업무 회사 |
| BAS | 01002 | `ed_01002` | 공장 | 회사 소속 공장 |
| BAS | 01003 | `ed_01003` | 공정 | 공장 소속 공정 |
| BAS | 01004 | `ed_01004` | 라인 | 공정 소속 생산 라인 |
| BAS | 01005 | `ed_01005` | 설비 | 라인 소속 설비 |

## 관계와 삭제 정책

```text
ed_01001 회사
  └─ ed_01002 공장
      └─ ed_01003 공정
          └─ ed_01004 라인
              └─ ed_01005 설비

ed_00001 메뉴 ── ed_00002 버튼 ── ed_00004 역할 권한 ── ed_00003 역할
ed_00005 공통코드
```

- 조직 계층의 부모 삭제는 `RESTRICT`로 보호한다.
- 메뉴-버튼과 역할-권한 연결은 부모 삭제 시 정리할 수 있지만, 운영 데이터는 논리 삭제를 우선한다.
- 모든 Provider에서 PK, FK, Unique Index, 계층 인덱스를 동일하게 검증한다.

## 확장 번호 정책

| 번호 범위 | 사용처 | 규칙 |
|---:|---|---|
| 00001~00999 | Edan SYS | 제품 공통 시스템 기능 |
| 01001~01999 | Edan BAS | 제품 공통 기준정보 |
| 10001~19999 | 고객 프로젝트 | 고객사별 업무 확장 |
| 90001~99999 | 실험·검증 | 상용 기본 패키지에 포함하지 않음 |

고객사 확장 테이블은 `ed_10001` 이상을 사용하고, 기존 기준 테이블의 이름·컬럼·키를 직접 변경하지 않는다. 공통 제품에 승격할 경우 별도 검토와 번호 예약을 거친다.

## 공통 컬럼 원칙

기본 엔터티에는 식별자, 코드, 명칭, 상태를 사용한다. 테넌트·조직 범위가 필요한 테이블에는 범위 컬럼을 추가한다. 감사가 필요한 테이블에는 UTC 생성·수정 시각과 행위자를 추가한다. 모든 테이블에 동일 컬럼을 무조건 복사하지 않고 데이터 소유권과 생명주기에 따라 적용한다.

## 완료 기준

- `EdanDbContext`에 기준 10개 테이블 매핑이 존재한다.
- SQLite, PostgreSQL, SQL Server, Oracle 마이그레이션에 동일한 기준 테이블이 존재한다.
- 모델 변경 없음 검사가 통과한다.
- 고객 프로젝트 확장 번호가 기준 번호와 충돌하지 않는다.
- 화면·API·권한은 테이블이 아니라 업무 계약을 통해 접근한다.
