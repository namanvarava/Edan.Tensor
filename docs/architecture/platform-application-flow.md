# 플랫폼 응용 흐름

## 업무 처리 순서
1. 요청 식별자와 입력값을 확인합니다.
2. 테넌트 상태를 확인합니다.
3. 조직과 프로젝트의 소속 관계를 확인합니다.
4. 중복 코드와 이메일을 확인합니다.
5. 도메인 객체를 생성합니다.
6. 저장소에 변경을 등록합니다.
7. 작업 단위로 변경 내용을 저장합니다.
8. 성공 식별자 또는 표준 오류를 반환합니다.

## 테넌트 격리 원칙
모든 플랫폼 생성 요청은 활성 테넌트를 기준으로 처리합니다. 조직은 요청 테넌트에 속해야 하며 프로젝트는 요청 테넌트와 조직에 모두 속해야 합니다. 자원과 정책도 동일한 범위 검증을 통과해야 합니다.

## 고유성 범위
- 테넌트 코드: 시스템 전체
- 조직 코드: 테넌트 내부
- 프로젝트 코드: 조직 내부
- 사용자 이메일: 테넌트 내부

응용 계층의 사전 중복 검사는 사용자 오류를 빠르게 반환하기 위한 절차입니다. 동시 요청의 최종 중복 방지는 데이터베이스 고유 제약 조건으로 보장해야 합니다.

## 오류 응답
응용 서비스는 업무 오류를 안정적인 오류 코드와 한글 설명으로 반환합니다. 데이터베이스 예외와 예상하지 못한 시스템 오류는 상위 예외 처리 계층에서 처리합니다.

## 의존성
Platform.Application은 Platform.Domain과 SharedKernel만 참조합니다. 데이터베이스 구현은 Platform.Infrastructure에 배치합니다.
