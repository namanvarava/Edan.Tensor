# 권한 감사 아카이브 구조

## 목적

권한 평가 감사 기록을 Tenant별 기간 단위로 독립 아카이브에 내보내고, 아카이브 내부 SHA-256 및 외부 기준 체크섬으로 무결성을 확인합니다.

## 구성

- Application의 `AuthorizationAuditArchiveService`가 감사 저장소에서 기간별 기록을 읽고 아카이브 문서를 직렬화합니다.
- `IAuthorizationAuditArchiveStore`는 저장 매체를 추상화합니다.
- Infrastructure의 파일 시스템 Adapter는 아카이브 식별자 기반으로 파일을 새로 생성하며 기존 파일을 덮어쓰지 않습니다.
- 아카이브 문서에는 스키마 버전, ArchiveId, TenantId, UTC 기간, 전체 감사 레코드 및 SHA-256이 포함됩니다.
- API는 Tenant Administrator만 생성 및 검증할 수 있습니다.

## 안전 규칙

- 기간은 최대 31일, 아카이브 레코드는 최대 100,000건입니다.
- 아카이브 생성 및 검증은 원본 감사 테이블을 변경하거나 삭제하지 않습니다.
- 내부 체크섬은 아카이브 페이로드의 직렬화 결과를 기준으로 계산합니다.
- 외부 보관 매체에 SHA-256, ArchiveId, TenantId 및 기간을 별도로 보관하고 검증 요청에 기준 체크섬을 전달해야 독립적인 변조 확인이 가능합니다.
- 파일 시스템 Adapter는 초기 로컬 운영용입니다. 다중 인스턴스 운영에서는 접근 제어와 내구성을 갖춘 공유 Object Storage Adapter로 교체해야 합니다.

## 후속 단계

보존 정책의 DB 관리, 법적 보존(Hold), 예약 작업, 작업 재시도, 승인 기반 원본 정리 및 외부 Object Storage 연동은 별도 단계에서 구현합니다. 현재 단계에서는 원본 삭제 기능을 제공하지 않습니다.

## Tenant별 보존 정책

- Tenant마다 감사 기록 보존 기간을 30~3,650일 범위에서 설정합니다. 정책이 없는 Tenant의 기본 조회값은 365일입니다.
- 법적 보존(Hold)을 활성화할 때는 사유를 필수로 기록하며 최대 500자까지 허용합니다.
- 정책 변경 시 변경 주체, 변경 유형, 변경 전·후 JSON 및 UTC 시각을 별도 추가 전용 테이블에 함께 저장합니다.
- 정책 갱신과 변경 이력 저장은 동일한 Unit of Work로 확정합니다.
- 현재 보존 기간은 정책 데이터로 관리되며 만료된 감사 기록을 자동 삭제하거나 아카이브에서 제거하는 작업은 실행하지 않습니다.
