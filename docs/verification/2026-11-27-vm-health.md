# 2026-11-27 외부 VM Health 검증

검증 대상: `192.168.56.101`

| Endpoint | 결과 |
|---|---|
| `http://192.168.56.101:5000/health` | HTTP 200, `Healthy` |
| `http://192.168.56.101:5000/health/database` | HTTP 200, `Connected`, Platform/Worker/DataSet/DataSetContent 모두 `true` |
| `http://192.168.56.101:5001/health` | HTTP 200, `Healthy` |
| `http://192.168.56.101:5001/health/database` | HTTP 200, `Connected`, Platform/Worker/DataSet/DataSetContent 모두 `true` |

TCP 연결도 다음 포트에서 성공했다.

- SSH `22`
- API `5000`
- Worker `5001`
- PostgreSQL `5432`
- SQL Server `1433`
- Oracle `1521`
- Keycloak `8443`

주의: SSH는 현재 공개키·비밀번호 인증이 필요해 자동 접속할 수 없었다. 따라서 이 기록은 Health와 TCP의 증적이며, 실제 Migration·스키마·백업 복구·인증 Provider 검증의 완료 증적을 대체하지 않는다.

## 추가 확인

소스에는 API의 `/health/edan` 엔드포인트가 존재하지만 VM의 `192.168.56.101:5000/health/edan`은 HTTP 404를 반환했다. 따라서 VM의 API 컨테이너가 현재 소스와 동일한 이미지가 아닌 것으로 판단한다. 최종 검증 전에 VM에서 최신 소스를 반영하여 API 이미지를 재빌드·재기동하고 `/health/edan`을 다시 확인해야 한다.
